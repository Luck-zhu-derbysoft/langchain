# 企业告警 Agent 学习与升级指南（迭代二）

> **目标：** 在迭代一的生产可用基础上，提升可观测、弹性、安全合规、规模化运营能力。
> **原则：** B 线生产加固是必做项；A 线 LangGraph 化是选做项，先试点、再按收益扩展。

## 一、迭代目标

- 将系统从“可以上线”推进到“可持续运营、可观测、可扩展”。
- 先完善交付、可观测、弹性、安全与容量规划，再评估架构升级。
- 不为使用框架而重写；测试不足时不开展大规模编排重构。

### A 线：LangGraph 编排升级（选做）

#### 6. 试点与扩散

| 技能点 | 当前判断 | 落地练习 | 优先级 |
|---|---|---|---|
| 编排改造收益判断 | 现有命令式链路可运行；复杂分支、恢复和 HITL 有一定改造价值 | 先用维护成本、测试结果和恢复需求评估收益 | ⚪ |

## 三、建议执行顺序

| 阶段 | 重点 | 交付物 |
|---|---|---|
| M1 | 复核交付基座与 CI/CD | 一键部署结果、流水线和部署检查清单 |
| M2 | 复核可观测能力 | 核心看板、告警演练及端到端追踪样例 |
| M3 | 弹性与安全合规 | 停机/故障注入报告、密钥轮换和扫描结果 |
| M4 | 规模化与成本 | 压测基线、HPA 验证及成本预算结论 |
| M5 | LangGraph 故障诊断试点 | 测试、Checkpoint 恢复结果及收益评估 |
| M6 | 按收益决定是否扩展 | 任务分解链路方案；未达收益则维持现状 |

## 四、LangGraph 试点门槛

- **先有测试兜底：** 核心链路测试覆盖不足时，不做大规模重构。
- **范围受控：** 只从故障诊断 L1→L4 链路开始，不一次性重写 `ChatService`。
- **结果可比较：** 以回归测试、断点恢复、可视化和维护成本评估收益。
- **按需扩散：** 试点收益明确后才考虑任务分解；简单链路继续使用现有实现。

## 五、验收标准

### B 线：企业级运营基线（必达）

- Docker Compose/Kubernetes 部署与健康探针正常。
- CI 质量门禁通过，供应链扫描有结果且告警可处理。
- 核心指标可视、告警可触达、追踪可关联。
- 密钥可轮换；审计可追溯；多租户资源边界生效。
- 有可复现的压测基线及容量、成本结论。

### A 线：编排升级（选达）

- 故障诊断试点支持状态化执行和断点恢复。
- 回归测试通过，试点收益有明确评估结论。
- 仅在试点有效时扩展，不图化简单链路。

## 六、速记

- **先运营、后重构：** B 线决定系统是否可持续运行，A 线解决特定复杂链路的维护问题。
- **先测量、再扩容：** 用 QPS、P99、错误率和成本数据指导容量规划。
- **安全持续化：** 密钥轮换、供应链扫描、审计和租户配额进入常规运维。
- **图化有条件：** 复杂分支、循环、HITL 或断点恢复有明确收益时才引入 LangGraph。
