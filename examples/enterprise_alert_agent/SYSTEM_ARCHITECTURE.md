## 🏗️ 系统分层架构

### Layer 1-7: 详细架构设计

系统采用 **7 层分层架构**，从上到下分别为：

1. **网络接入层** - Web/API/WebSocket 入口
2. **API 路由层** - FastAPI 路由分发
3. **业务逻辑层** - ChatService 核心编排
4. **智能体与协调层** - Agent Registry + Orchestrator
5. **基础设施层** - LLM/RAG/内存/工具/故障
6. **可观测性层** - 指标/告警/追踪/日志
7. **数据持久化层** - PostgreSQL/Redis/ChromaDB/MySQL

## 📊 关键模块详解

### 🤖 Agent Registry (智能体注册表)

```
┌──────────────────────────────────────────────────────┐

├──────────────────────────────────────────────────────┤

│ sql_agent       (优先级 90)   - 数据库查询 Agent    │
│ rag_agent       (优先级 80)   - 知识检索 Agent      │
└──────────────────────────────────────────────────────┘
```

### 🧠 ChatService 核心流程

13 个关键处理步骤：
1. **意图分类** (LLM) → 2. **工具解析** (模块激活)
3. **工具选择** (LLM) → 4. **Agent 选择** (注册表)
5. **内存加载** (Redis/PG) → 6. **RAG 检索** (ChromaDB)
7. **任务分解** (LLM) → 8. **并行执行** (ThreadPoolExecutor)
9. **LLM 生成** (Qwen) → 10. **内存保存** (Redis/PG)
11. **指标收集** (MetricsCollector) → 12. **告警触发** (AlertManager)
13. **追踪完成** (LangSmith)

### 📊 数据流向

```
用户输入 → API 层 → 意图分类 → 工具解析 → 内存/RAG 加载 
  ↓                                             ↓
  └─→ Agent 协调 → 任务分解 → 并行执行 → LLM 生成
        ↓
    故障诊断 → 人工干预 → 告警触发
        ↓
    指标记录 → LangSmith 追踪 → HTTP 返回
```

### ⚡ 性能特征

| 阶段 | 耗时 | 优化点 |
|-----|------|--------|
| 意图分类 | 10ms | LLM 缓存 |

| 任务分解 | 30ms | 规则化 |
| 并行执行 | 90ms | 并行度 |
